## Flag for `/remember`

This incident is a **new, distinct failure mode** and should be recorded as its own
`memory/lessons-learned.md` entry, not merged into the existing 2026-08-10 Sprint-1
iCloud-Drive-parallelism entry it superficially resembles:

- **What happened:** A single commit (`042452c`), authored during what looks like a
  `/plan`-phase-adjacent orchestrating session (not a `task-runner` subagent, and not part of any
  parallel wave — only one agent was acting at the time), was titled "fix: correct App
  Group/iCloud container identifier drift (com.kv.apin -> com.apin.app)" but its actual diff ran
  exactly backwards: it changed the already-correct `group.com.apin.app` back to the broken
  `group.com.kv.apin` across two Swift-source literals and their two pinned regression tests, then
  described itself in its own commit message as fixing that drift. It committed cleanly (no test
  run gated the commit), sat in history, and was only caught by the next `/qa` pass's independent
  re-run of the app's test suite.
- **How it differs from the Sprint-1 iCloud-Drive lesson:** that lesson is about *parallel*
  `task-runner` agents under iCloud Drive producing file-provider "conflicted copy" duplicates —
  a sync-layer artifact from concurrent writes. This incident involved **one agent acting alone**,
  committing a stale or inverted working-tree diff (plausibly a leftover unsynced snapshot,
  per `b7c1536`'s own commit message's plausible-cause note) without reading the actual diff
  content against its own stated intent before committing. The common thread is "this repo lives
  under iCloud Drive and that has caused stale/inverted content to get committed," but the
  mechanism (single-agent commit hygiene vs. multi-agent sync race) is different enough to warrant
  a separate entry, per this task's explicit instruction.
- **Suggested prevent-next-time rule:** before committing a diff whose message claims to fix a
  specific value mismatch (X → Y), the committing agent/session must `git diff` (or equivalent)
  and confirm the actual diff direction matches the stated direction for every hunk — not just
  trust that the working tree reflects the intended change. This is a general commit-hygiene rule,
  candidate for promotion to `memory/coding-standards.md` alongside the existing iCloud-Drive
  parallelism rule, but as its own line item since the trigger condition (single-agent stale-diff
  commit vs. multi-agent sync race) differs.
- **Also update:** `memory/technical-debt.md`'s App Group entry, whose narrative is now stale
  (see "Known bugs" above).
